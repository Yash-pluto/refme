## Getting Started

Microservices break a monolith into small, independently deployable services. Each service owns its own data and API, enabling teams to move faster and scale independently.

---

## Core principles

- bounded context for each service
- independent deployment and scaling
- clear API contracts between services
- decentralized data ownership

---

## Communication

Microservices communicate via HTTP/REST, gRPC, or asynchronous messaging.

- synchronous calls are easy to reason about
- asynchronous events improve resilience and decoupling

---

## Deployment considerations

- service discovery
- versioned APIs
- monitoring and tracing across boundaries
- automation for deployment and rollback

---

## Trade-offs

Microservices offer flexibility, but add complexity in distributed systems, network failure handling, and operational overhead.
